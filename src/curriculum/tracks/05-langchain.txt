=== lc-01 | Wrapping a chat model | 2
::: story
From here on, `FakeLLM` stands in for a real model (type `setup` to read its
code). `FakeLLM(rules={"hello": "Hi!"})` replies by keyword;
`FakeLLM(responses=["a", "b"])` replies from a queue. Every prompt it receives
is recorded in `llm.calls`.
LangChain chat models accept EITHER a string or a list of messages, and
return an AIMessage. Let's build that adapter.
::: setup fake_llm
::: task
Write `class ChatModel(llm, system=None)`:
- `invoke(input)`: if input is a str, turn it into `[{"role": "user", "content": input}]`;
  if it's a list, copy it. If `system` is set, prepend a system message.
  Pass the message list to `llm.invoke(...)` and return
  `{"role": "assistant", "content": <reply>}`.
- `batch(inputs)` -> list of invoke results.
::: starter
class ChatModel:
    def __init__(self, llm, system=None):
        self.llm = llm
        self.system = system

    def invoke(self, input):
        pass
::: solution
class ChatModel:
    def __init__(self, llm, system=None):
        self.llm = llm
        self.system = system

    def invoke(self, input):
        if isinstance(input, str):
            messages = [{"role": "user", "content": input}]
        else:
            messages = list(input)
        if self.system:
            messages = [{"role": "system", "content": self.system}] + messages
        return {"role": "assistant", "content": self.llm.invoke(messages)}

    def batch(self, inputs):
        return [self.invoke(x) for x in inputs]
::: hint
`isinstance(input, str)` tells you which shape you got.
::: hint
The FakeLLM records what you sent in `llm.calls` — the tests inspect it.
::: test string input
llm = FakeLLM(rules={"hello": "Hi there!"})
model = ChatModel(llm)
assert model.invoke("hello bot") == {"role": "assistant", "content": "Hi there!"}
assert llm.calls[0] == [{"role": "user", "content": "hello bot"}]
::: test system prompt and lists
llm = FakeLLM(responses=["ok"])
model = ChatModel(llm, system="be brief")
history = [{"role": "user", "content": "q"}]
model.invoke(history)
assert llm.calls[0] == [{"role": "system", "content": "be brief"}, {"role": "user", "content": "q"}]
assert history == [{"role": "user", "content": "q"}], "don't mutate the caller's list"
::: test batch

assert [r["content"] for r in model.batch(["a", "b"])] == ["1", "2"]

=== lc-02 | The Runnable interface | 2
::: story
LangChain's core idea: EVERYTHING (prompts, models, parsers, retrievers,
whole chains) is a `Runnable` with the same methods: `invoke`, `batch`,
`stream`. Uniform interfaces are what make components composable.
::: task
1. `class Runnable` (base): `invoke(input)` raises `NotImplementedError`;
   `batch(inputs)` -> list of invoke results; `stream(input)` is a generator
   that yields the single invoke result (subclasses may override).
2. `class RunnableLambda(Runnable)` wraps a function: `invoke(x)` -> `fn(x)`.
   Its `repr` is `RunnableLambda(<function name>)`.
3. `class WordStreamer(Runnable)`: invoke returns the text unchanged, but
   `stream(text)` yields each word separately (overrides the default).
::: starter
class Runnable:
    pass

class RunnableLambda(Runnable):
    pass

class WordStreamer(Runnable):
    pass
::: solution
class Runnable:
    def invoke(self, input):
        raise NotImplementedError

    def batch(self, inputs):
        return [self.invoke(x) for x in inputs]

    def stream(self, input):
        yield self.invoke(input)

class RunnableLambda(Runnable):
    def __init__(self, fn):
        self.fn = fn

    def invoke(self, input):
        return self.fn(input)

    def __repr__(self):
        return f"RunnableLambda({self.fn.__name__})"

class WordStreamer(Runnable):
    def invoke(self, input):
        return input

    def stream(self, input):
        for word in input.split():
            yield word
::: hint
`stream` in the base class is just `yield self.invoke(input)`.
::: hint
`self.fn.__name__` gives a function's name for the repr.
::: test base
try:
    Runnable().invoke(1)
    assert False
except NotImplementedError:
    pass
::: test lambda
double = RunnableLambda(lambda x: x * 2)
assert double.invoke(4) == 8 and double.batch([1, 2]) == [2, 4]
assert list(double.stream(3)) == [6]
def shout(s): return s.upper()
assert repr(RunnableLambda(shout)) == "RunnableLambda(shout)"
::: test word streamer
w = WordStreamer()
assert w.invoke("a b") == "a b" and list(w.stream("a b c")) == ["a", "b", "c"]
assert isinstance(w, Runnable) and w.batch(["x"]) == ["x"]

=== lc-03 | LCEL: the pipe operator | 3
::: story
`prompt | llm | parser` is LangChain Expression Language. It works because
Runnable defines `__or__`: `a | b` calls `a.__or__(b)` which returns a
`RunnableSequence` that feeds a's output into b.
If the left side isn't a Runnable (e.g. a plain function), Python tries the
RIGHT side's `__ror__`.
::: task
1. `coerce(obj)`: return obj if it's a Runnable; wrap callables in
   `RunnableLambda`; otherwise raise `TypeError`.
2. Give `Runnable` an `__or__(other)` and `__ror__(other)`, both returning a
   `RunnableSequence` (coercing the non-Runnable side).
3. `class RunnableSequence(Runnable)`: stores `steps` (a flat list — piping
   sequences together must NOT nest them), and `invoke` runs each step in order.
::: starter

        raise NotImplementedError

    def batch(self, inputs):
        return [self.invoke(x) for x in inputs]

class RunnableLambda(Runnable):
    def __init__(self, fn):
        self.fn = fn

    def invoke(self, input):
        return self.fn(input)

def coerce(obj):
    pass

class RunnableSequence(Runnable):
    pass
::: solution
class Runnable:
    def invoke(self, input):
        raise NotImplementedError

    def batch(self, inputs):
        return [self.invoke(x) for x in inputs]

    def __or__(self, other):
        return RunnableSequence(self, coerce(other))

    def __ror__(self, other):
        return RunnableSequence(coerce(other), self)

class RunnableLambda(Runnable):
    def __init__(self, fn):
        self.fn = fn

    def invoke(self, input):
        return self.fn(input)

def coerce(obj):
    if isinstance(obj, Runnable):
        return obj
    if callable(obj):
        return RunnableLambda(obj)
    raise TypeError(f"cannot pipe {type(obj).__name__}")

class RunnableSequence(Runnable):
    def __init__(self, *steps):
        self.steps = []
        for step in steps:
            if isinstance(step, RunnableSequence):
                self.steps.extend(step.steps)
            else:
                self.steps.append(step)

    def invoke(self, input):
        for step in self.steps:
            input = step.invoke(input)
        return input
::: hint
In `RunnableSequence.__init__`, if a step is itself a RunnableSequence, `extend` with its steps instead of appending it.
::: hint
`__ror__(self, other)` handles `function | runnable`: return `RunnableSequence(coerce(other), self)`.
::: test pipe
add1 = RunnableLambda(lambda x: x + 1)
dbl = RunnableLambda(lambda x: x * 2)
chain = add1 | dbl
assert isinstance(chain, RunnableSequence) and chain.invoke(3) == 8
::: test flat steps
a, b, c = (RunnableLambda(lambda x: x) for _ in range(3))
assert len((a | b | c).steps) == 3, "sequences must be flattened"
::: test functions on either side
chain = (lambda s: s.strip()) | RunnableLambda(str.upper) | (lambda s: s + "!")
assert chain.invoke("  hi ") == "HI!"
assert chain.batch(["a", "b"]) == ["A!", "B!"]
::: test bad pipe

    RunnableLambda(str) | 42
    assert False
except TypeError:
    pass

=== lc-04 | Parallel branches & passthrough | 3
::: story
Real chains need fan-out: run several runnables on the SAME input and collect
a dict. In LCEL a plain dict in a pipe means "run these in parallel":
```
{"context": retriever, "question": RunnablePassthrough()} | prompt
```
The base Runnable/RunnableLambda/RunnableSequence are provided (type `setup`).
::: setup
class Runnable:
    def invoke(self, input):
        raise NotImplementedError

    def batch(self, inputs):
        return [self.invoke(x) for x in inputs]

    def __or__(self, other):
        return RunnableSequence(self, coerce(other))

    def __ror__(self, other):
        return RunnableSequence(coerce(other), self)

class RunnableLambda(Runnable):
    def __init__(self, fn):
        self.fn = fn

    def invoke(self, input):
        return self.fn(input)

class RunnableSequence(Runnable):
    def __init__(self, *steps):
        self.steps = list(steps)

    def invoke(self, input):
        for step in self.steps:
            input = step.invoke(input)
        return input

def coerce(obj):
    if isinstance(obj, Runnable):
        return obj
    if isinstance(obj, dict) and "RunnableParallel" in globals():
        return globals()["RunnableParallel"](obj)
    if callable(obj):
        return RunnableLambda(obj)
    raise TypeError(f"cannot pipe {type(obj).__name__}")
::: task
1. `class RunnableParallel(Runnable)`: `RunnableParallel(steps_dict)` coerces
   each value; `invoke(x)` returns `{key: step.invoke(x)}`. (Once it exists,
   `coerce` turns dicts into it automatically, so `{...} | something` works.)
2. `class RunnablePassthrough(Runnable)`: returns its input unchanged.
   Add a classmethod `assign(**steps)` returning a Runnable that takes a dict
   and returns a NEW dict with the original keys plus each step's result
   (each step receives the original dict).
::: starter
class RunnableParallel(Runnable):
    pass

class RunnablePassthrough(Runnable):
    pass
::: solution
class RunnableParallel(Runnable):
    def __init__(self, steps):
        self.steps = {k: coerce(v) for k, v in steps.items()}

    def invoke(self, input):
        return {k: step.invoke(input) for k, step in self.steps.items()}

class RunnablePassthrough(Runnable):
    def invoke(self, input):
        return input

    @classmethod
    def assign(cls, **steps):
        parallel = RunnableParallel(steps)
        return RunnableLambda(lambda d: {**d, **parallel.invoke(d)})
::: hint
`assign` can reuse RunnableParallel: compute the new keys, then merge `{**d, **new}`.
::: hint
Remember `coerce(v)` so plain lambdas work as branch values.
::: test parallel
p = RunnableParallel({"up": str.upper, "len": len})
assert p.invoke("abc") == {"up": "ABC", "len": 3}
::: test dict in a pipe
chain = RunnableLambda(str.strip) | {"text": RunnablePassthrough(), "words": lambda s: len(s.split())}
assert chain.invoke("  a b  ") == {"text": "a b", "words": 2}
::: test assign
step = RunnablePassthrough.assign(total=lambda d: d["a"] + d["b"])
data = {"a": 1, "b": 2}
assert step.invoke(data) == {"a": 1, "b": 2, "total": 3}
assert data == {"a": 1, "b": 2}, "assign must not mutate its input"

=== lc-05 | Output parsers | 3
::: story
Models return messages; your code wants Python objects. Output parsers sit at
the end of a chain and convert. The `mini_lc` prelude provides `Runnable`
(type `setup` to read it). Model output may be a str or an AIMessage-like
dict `{"role": "assistant", "content": "..."}`.
::: setup mini_lc
::: task
Subclass `Runnable` to write:
1. `TextParser`: returns the content as a stripped str (works for str or dict).
2. `ListParser`: parses either comma-separated text (`"a, b, c"`) or one item
   per line with optional bullets (`"- a\n* b\n1. c"`) into a list of
   non-empty stripped strings. If the text contains newlines, treat it as
   lines; otherwise split on commas.
3. `JsonParser`: parses the content as JSON, also handling a fenced code
   block; on failure raise `ValueError("could not parse JSON: ...")`.
::: starter
import json
import re

class TextParser(Runnable):
    pass

class ListParser(Runnable):
    pass

class JsonParser(Runnable):
    pass
::: solution
import json
import re

def _content(x):
    return str(x.get("content", "")) if isinstance(x, dict) else str(x)

class TextParser(Runnable):
    def invoke(self, input):
        return _content(input).strip()

class ListParser(Runnable):
    def invoke(self, input):
        text = _content(input).strip()
        if "\n" in text:
            items = [re.sub(r"^\s*(?:[-*]|\d+\.)\s*", "", line) for line in text.splitlines()]
        else:
            items = text.split(",")
        return [i.strip() for i in items if i.strip()]

class JsonParser(Runnable):
    def invoke(self, input):
        text = _content(input)
        fenced = re.search(r"`{3}(?:json)?\s*(.*?)`{3}", text, re.S)
        if fenced:
            text = fenced.group(1)
        try:
            return json.loads(text)
        except json.JSONDecodeError as exc:
            raise ValueError(f"could not parse JSON: {exc}") from exc
::: hint
A tiny helper `_content(x)` that handles both str and dict keeps every parser short.
::: hint
Strip bullets with `re.sub(r"^\s*(?:[-*]|\d+\.)\s*", "", line)`.

::: test list parser

assert ListParser().invoke({"content": "- apples\n* pears\n1. plums\n\n"}) == ["apples", "pears", "plums"]
::: test json parser

assert JsonParser().invoke('{"a": 1}') == {"a": 1}

=== lc-07 | Build the @tool decorator | 4
::: story
To let a model call your function, you must describe it as a JSON schema:
name, description, and typed parameters. LangChain's `@tool` reads all of
that from the function signature and docstring using `inspect`:
```
import inspect
sig = inspect.signature(fn)
for p in sig.parameters.values():
    p.name, p.annotation, p.default is inspect.Parameter.empty
inspect.getdoc(fn)
```
::: task
Write a decorator `tool` that turns a function into a `Tool` object with:
- `name` (function name) and `description` (first line of the docstring;
  raise `ValueError` at decoration time if there is no docstring)
- `parameters`: dict name -> `{"type": <json type>, "required": bool}` with
  types `str->"string"`, `int->"integer"`, `float->"number"`, `bool->"boolean"`,
  `list->"array"`, `dict->"object"`, anything else `"string"`. Required =
  no default value.
- `invoke(args: dict)`: raise `ValueError` if a required arg is missing or an
  unknown arg is passed; otherwise call the function with `**args`
- `schema()`: `{"name", "description", "parameters": {"type": "object",
  "properties": {name: {"type": ...}}, "required": [names in order]}}`
- calling the Tool directly (`t(1, 2)`) still calls the original function.
::: starter
import inspect

JSON_TYPES = {str: "string", int: "integer", float: "number", bool: "boolean", list: "array", dict: "object"}

class Tool:
    pass

def tool(fn):
    pass
::: solution
import inspect

JSON_TYPES = {str: "string", int: "integer", float: "number", bool: "boolean", list: "array", dict: "object"}

class Tool:
    def __init__(self, fn):
        doc = inspect.getdoc(fn)
        if not doc:
            raise ValueError(f"tool {fn.__name__!r} needs a docstring")
        self.fn = fn
        self.name = fn.__name__
        self.description = doc.splitlines()[0]
        self.parameters = {}
        for p in inspect.signature(fn).parameters.values():
            self.parameters[p.name] = {
                "type": JSON_TYPES.get(p.annotation, "string"),
                "required": p.default is inspect.Parameter.empty,
            }

    def __call__(self, *args, **kwargs):
        return self.fn(*args, **kwargs)

    def invoke(self, args):
        unknown = set(args) - set(self.parameters)
        if unknown:
            raise ValueError(f"unknown arguments: {sorted(unknown)}")
        missing = [n for n, p in self.parameters.items() if p["required"] and n not in args]
        if missing:
            raise ValueError(f"missing arguments: {missing}")
        return self.fn(**args)

    def schema(self):
        return {
            "name": self.name,
            "description": self.description,
            "parameters": {
                "type": "object",
                "properties": {n: {"type": p["type"]} for n, p in self.parameters.items()},
                "required": [n for n, p in self.parameters.items() if p["required"]],
            },
        }

def tool(fn):
    return Tool(fn)
::: hint
`JSON_TYPES.get(p.annotation, "string")` maps the annotation; unannotated params have `inspect.Parameter.empty` and fall back to "string".
::: hint
Compute unknown args with a set difference: `set(args) - set(self.parameters)`.
::: test metadata

=== lc-08 | The tool-calling loop | 4
::: story
How agents actually work:
1. send messages to the model
2. if the reply contains `tool_calls`, run each tool, append a `tool` message
   with the result, and go back to 1
3. otherwise the reply is the final answer
The FakeLLM is scripted to return tool calls like:
```
{"content": "", "tool_calls": [{"id": "c1", "name": "add", "args": {"a": 2, "b": 3}}]}
```
`tool` from mini_lc gives objects with `.name` and `.invoke(args_dict)`.
::: setup fake_llm mini_lc
::: task
Write `run_agent(llm, tools, question, max_steps=5)`:
- start with `messages = [{"role": "user", "content": question}]`
- each step: `reply = llm.invoke(messages)`
  - if reply is a dict with non-empty `tool_calls`: append
    `{"role": "assistant", "content": reply.get("content", ""), "tool_calls": reply["tool_calls"]}`,
    then for each call append
    `{"role": "tool", "tool_call_id": call["id"], "content": str(result)}`.
    Unknown tool -> content `"Error: unknown tool <name>"`; a tool that raises
    -> content `"Error: <exception message>"` (the agent can recover!)
  - otherwise return the final answer text (reply itself if str, else its "content")
- if `max_steps` model calls happen without a final answer, raise `RuntimeError`.
Return value: `(answer, messages)` — messages includes the final assistant message.
::: starter
def run_agent(llm, tools, question, max_steps=5):
    by_name = {t.name: t for t in tools}
    messages = [{"role": "user", "content": question}]
    pass
::: solution
def run_agent(llm, tools, question, max_steps=5):
    by_name = {t.name: t for t in tools}
    messages = [{"role": "user", "content": question}]
    for _ in range(max_steps):
        reply = llm.invoke(list(messages))
        if isinstance(reply, dict) and reply.get("tool_calls"):
            messages.append({"role": "assistant", "content": reply.get("content", ""), "tool_calls": reply["tool_calls"]})
            for call in reply["tool_calls"]:
                t = by_name.get(call["name"])
                if t is None:
                    result = f"Error: unknown tool {call['name']}"
                else:
                    try:
                        result = t.invoke(call["args"])
                    except Exception as exc:
                        result = f"Error: {exc}"
                messages.append({"role": "tool", "tool_call_id": call["id"], "content": str(result)})
            continue
        answer = reply if isinstance(reply, str) else reply.get("content", "")
        messages.append({"role": "assistant", "content": answer})
        return answer, messages
    raise RuntimeError(f"no final answer after {max_steps} steps")
::: hint
Use a `for _ in range(max_steps)` loop; `continue` after handling tool calls, `return` on a final answer, `raise` after the loop.
::: hint
Wrap `t.invoke(call["args"])` in try/except so a broken tool becomes an error message instead of a crash.
::: test single tool call

    {"content": "", "tool_calls": [{"id": "c1", "name": "add", "args": {"a": 2, "b": 3}}]},
    "The answer is 5.",

::: solution
class SessionChat:
    def __init__(self, llm, window=4, system=None):
        self.llm = llm
        self.window = window
        self.system = system
        self.store = {}

    def invoke(self, text, session_id="default"):
        history = self.store.setdefault(session_id, [])
        user_msg = {"role": "user", "content": text}
        recent = history[-self.window:] if self.window > 0 else []
        prompt = ([{"role": "system", "content": self.system}] if self.system else []) + recent + [user_msg]
        reply = self.llm.invoke(prompt)
        history.append(user_msg)
        history.append({"role": "assistant", "content": reply})
        return reply

    def history(self, session_id):
        return list(self.store.get(session_id, []))

    def clear(self, session_id):
        self.store.pop(session_id, None)
::: hint
`self.store.setdefault(session_id, [])` returns the existing list or inserts a new one.
::: hint
Watch out: `history[-0:]` is the whole list. Handle window=0 separately.

=== lc-10 | A full RAG chain | 4
::: story
Retrieval-Augmented Generation: fetch relevant docs, stuff them into the
prompt, and let the model answer from them. In LCEL:
```
chain = (
    {"context": retriever | format_docs, "question": RunnablePassthrough()}
    | prompt | llm | StrOutputParser()
)
```
A `KeywordRetriever` (a Runnable: question -> list of doc dicts) is provided.
::: setup fake_llm mini_lc
class KeywordRetriever(Runnable):
    """Returns docs sharing the most words with the query (top k)."""

    def __init__(self, docs, k=2):
        self.docs, self.k = docs, k

    def invoke(self, query):
        q = set(query.lower().split())
        scored = [(len(q & set(d["text"].lower().split())), i, d) for i, d in enumerate(self.docs)]
        scored = [s for s in scored if s[0] > 0]
        scored.sort(key=lambda s: (-s[0], s[1]))
        return [d for _, _, d in scored[: self.k]]

RAG_PROMPT = PromptTemplate.from_template(
    "Answer using only this context:\n{context}\n\nQuestion: {question}"
)

def format_docs(docs):
    if not docs:
        return "(no relevant documents)"
    return "\n".join(f"[{d['source']}] {d['text']}" for d in docs)

def build_rag_chain(retriever, llm):
    return (
        {"context": retriever | format_docs, "question": RunnablePassthrough()}
        | RAG_PROMPT | llm | StrOutputParser()
    )

def build_rag_with_sources(retriever, llm):
    answer = (
        (lambda d: {"context": format_docs(d["docs"]), "question": d["question"]})
        | RAG_PROMPT | llm | StrOutputParser()
    )
    return (
        RunnableParallel({"docs": retriever, "question": RunnablePassthrough()})
        | {"answer": answer, "sources": lambda d: [doc["source"] for doc in d["docs"]]}
    )
::: hint
A dict at the start of a pipe runs both branches on the same input (the question).
::: hint
For sources: first produce `{"docs": ..., "question": ...}`, then a second parallel step computes answer and sources from that dict.
::: hint
Gotcha: `{...} | {...}` is Python's dict MERGE operator, not a pipe! Wrap the first dict in `RunnableParallel(...)` so the `|` becomes LCEL.
